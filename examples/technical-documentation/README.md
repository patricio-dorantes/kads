# Example: finding the right documentation home

This illustrative page demonstrates ordinary technical documentation without IDs or front matter. Its subject is how a contributor uses KADS's templates; it is a summary of the [template guide](../../templates/README.md), not a separate template policy.

## Choose an outline

For an explanation, procedure, reference, or design page, begin with the [technical-document outline](../../templates/technical-document.md). For research findings that fit on one page, use the [research-report outline](../../templates/research-report.md).

Use the [tracked-record outlines](../../templates/README.md) when the project needs independent identity and lifecycle. A link to a page does not by itself require a record ID.

## Put the document in the project

1. Read the consuming project's documentation index and adoption note.
2. Search for an existing page covering the subject and scope.
3. If a new page is needed, copy the selected outline outside the KADS submodule.
4. Replace placeholders, remove irrelevant sections, and make links resolve from the destination.
5. Link the result from the nearest useful index and apply the project's review process.

Completion means the page answers its reader's question, contains no template instructions, and can be reached from the project's navigation. No command execution is involved in this example.

## Scope and maintenance

This example covers KADS 0.9.0. The [adoption guide](../../docs/adoption-guide.md) explains project layout and review ownership. Review this page if the template or adoption guidance changes.
